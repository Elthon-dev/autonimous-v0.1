Motivation: the v0.5.0 engine still gated everything behind a finite wake-phrase
list, so only four phrasings could ever start the pipeline. This release removes
the gate and decides activation from the *meaning* of the transcript, using a
layered pipeline: **VAD → streaming open-vocabulary ASR → weighted
addressing-intent classifier → confidence decider → conversation state**.

What shipped:
- `VoiceActivityDetector` — arithmetic energy VAD with an adaptive noise floor
  and hysteresis; no model, negligible idle cost.
- `AudioRingBuffer` — bounded pre-roll so the first syllable is not clipped when
  speech is confirmed.
- `AddressingDetector` — weighted linguistic cues (vocative, address frames,
  meta-requests, imperatives, questions, openers) with third-person "bro"
  subtraction. Generalises to unseen wording; not a phrase whitelist.
- `ActivationDecider` — high / ambiguous / low bands, refractory window and
  per-utterance dedup.
- `ConversationSession` — follow-up window, idle timeout, turn phases.
- `DetectionConfig`(+`DetectionConfigStore`) — persisted thresholds/toggles.
- `AudioIO` — best-effort AEC and cancellable playback for barge-in.
- `VoiceSession` — continuous listen loop with per-turn error resilience.
- Legacy keyword spotter retained; optional non-decisive evidence, off by default.
- UI: `DetectionSettingsSection` replaces `WakeTriggerSection`; `DETECT`
  self-test exercises VAD→ASR→classifier→decision on live mic audio.

Then: `docs/ADDRESSING_ENGINE.md` describes the design, weights, policy and
trade-offs. **No acoustic metric (precision/recall, false-activations/hour,
decision latency, peak memory) is measured** — that needs labelled real audio.
The diagnostics screen exposes the live counters so they can be computed from a
real session. Device behaviour (barge-in, AEC, mic gate) remains **DEVICE-TODO**.

| Run link | https://github.com/Elthon-dev/autonimous-v0.1/actions/runs/38480196145 |

Motivation: on the Oppo A18 the app opened, enabled voice mode, showed the mic
foreground-service notification, detected the exact phrase "Hey Bro" — **then
crashed**. There were no device logs and the static review could not pin the
cause, so this version (a) makes the crash *observable* and (b) hardens the
wake→ASR→LLM→TTS lifecycle and widens the wake engine.

Wake engine:
- Four triggers, toggled at runtime: **Hey Bro**, **Bro**, **Yo Bro**,
  **Okay Bro**, each with its own boost `:score` and `#threshold`.
- Tokens are baked at build time (the BPE tokenizer only exists then):
  `keywords.txt` = `▁HE Y ▁B RO`, `▁B RO`, `▁ Y O ▁B RO`, `▁OKAY ▁B RO`.
  Regenerated by `scripts/fetch_voice_assets.sh`; the committed lock matches CI
  byte-for-byte (129 bytes, `d13c25f4…6bff6a`).
- Two-stage verification (`WakeVerifier`): an energy gate + refractory window drop
  phantom / duplicate hits *before* the expensive ASR stage.
- `RequestExtractor`: strips only the trigger phrase and keeps words spoken
  before it ("what's the weather, hey bro" → "what's the weather").

Crash capture:
- `CrashReporter` chains the default uncaught-exception handler and reads
  `ApplicationExitInfo` history (native crash, ANR, low-memory kill), writing
  `filesDir/crashes/last_crash.txt`; shown in the diagnostics panel and the copy
  report. **The crash root cause is still unconfirmed** until the phone produces
  a report.

Lifecycle hardening:
- KWS + ASR `OnlineStream`s are released every turn (via `release()` in a
  `finally`) — previously native handles leaked per turn.
- `WakeWordDetector` reads the active-keyword file (no runtime-string
  duplication); `WakeConfig.writeActive` renders the enabled subset to
  `keywords.active.txt`.

Known limitations (still true):
- The post-"Hey Bro" **crash is not proven fixed** — only now *observable*.
- Wake thresholds are unverified on the Oppo A18; the shipped defaults are
  `2.0/0.25` (Hey Bro), `2.0/0.50` (Bro), `2.0/0.35` (Yo Bro, Okay Bro). Expect
  tuning. Standalone "Bro" is on by default and may over-trigger.
- No conversation context, no barge-in, no follow-up window; English only.

Still needs DEVICE: install `bro-exe-v0.5.0-6ad160b-debug.apk`, run the six stage
tests, speak each of the four triggers, and — if it still crashes — send the
diagnostics report (`last_crash.txt`).

Root cause of "wake word never fires while the notification says *Listening for
Hey Bro*": the capture path opened `AudioSource.VOICE_RECOGNITION` (some MediaTek /
ColorOS HALs starve that buffer) and swallowed negative `AudioRecord.read` results
as empty frames, producing a silent busy-loop. Full evidence trail in
`docs/WAKE_WORD_ROOT_CAUSE.md`.

Changes since 0.3.0:
- `AudioIO`: capture source is now `MIC` (matches the upstream sherpa-onnx KWS
  sample); init/recording state validated; negative reads throw
  `AudioCaptureException` instead of spinning on phantom empty frames; explicit
  `stop()`/`release()`.
- `VoiceDiagnostics`: process-wide live snapshot — state, mic frame count, level,
  peak-hold, wake hits, last ASR/reply/error — plus a bounded event log and a
  copyable report. Silence is now distinguishable from signal.
- `VoiceSelfTest`: on-device `MIC` / `WAKE` / `ASR` / `AI` / `TTS` / `FULL` stage
  tests that drive the real engines (no ADB needed).
- `VoiceService`: mirrors state/detail into diagnostics; new `ACTION_TEST` entry
  point runs a stage test while Voice Mode is off.
- `AppRoot`: single Voice-Mode switch + diagnostics panel (live mic meter, signal
  verdict, counters, event log) + six stage-test buttons + "Copy report".
- Tests added: `AudioFrameTest` (`pcm16ToFloat`), `VoiceDiagnosticsTest`
  (level/peak-hold/ring). CI green.

Still needs DEVICE confirmation: run the six stage tests on the Oppo A18 and
confirm the mic meter shows a signal. Stages 1–5 of `VOICE_TEST_PLAN.md`.

### Known bugs & limitations (honest)
1. Wake word is the single phrase **"Hey Bro"** — the standalone word **"bro" inside
   ordinary sentences is not yet detected**.
2. **No conversation context across turns** — the native engine clears its KV cache
   and re-decodes system+user each turn, so follow-ups cannot rely on the prior turn.
3. **No barge-in** — speaking while Bro talks does not interrupt it; the loop is
   strictly half-duplex.
4. **No follow-up window** — every utterance needs the wake word (the silence
   timeout behaviour is unverified). Pre-roll (0.3.0) keeps the words *around* the
   trigger, but detection still requires the phrase.
5. The LLM is **loaded then unloaded every turn** (memory-safe, but adds latency).
6. Web search fires only on explicit phrases ("search for / look up / google / find"),
   not on the model's own judgement.
7. First-launch extraction shows a status word, **not byte progress**.
8. English only. Filipino/Cebuano not supported.
9. Interruption/stop timing, screen-off, and audio-focus behaviour are **unverified**.
